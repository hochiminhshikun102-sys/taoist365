# Object civilization governance

## QUICK CONTEXT BOOTSTRAP

- Objects are **room structure**, not a catalog voice. Long-lived sites risk “showroom” energy when every item narrates.
- Civilization governance pushes **foreground fatigue, anti-display bias, and quiet defaultness** through thinning—not through new object UI.

## THIS DOCUMENT DEFINES

How object civilization bundles align **`RealObjectPresencePanel`**, **`ObjectPermanenceStrip`**, and gates with **`invisibleInfrastructureStructuralThinning.combinedProseBias`** and related flags (after infra pass).

## CORE PRINCIPLES

- **Furniture, not highlights**: prose thins; disappearance windows lengthen on high-bias days.
- **Regulation first**: `regulatedForegroundIds` and structural absence still win; thinning never overrides hard gates.
- **Anti-catalog tone**: combined bias lowers operational language without adding explanatory chrome.

## WHY OBJECTS MUST BECOME ROOM STRUCTURE

Catalog metaphors invite browsing urgency and comparison loops. Room-structure metaphors invite **low refresh** and **long coexistence** with the same few surfaces.

## MAINTENANCE NOTES

- When `/objects` feels empty, adjust thinning weights or regulation caps—not new grids or filters.
