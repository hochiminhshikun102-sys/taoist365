# Long-lived civilization presence

## QUICK CONTEXT BOOTSTRAP

- Longevity for this project means **the same URL stays acceptable years later**—not that it grows feature count.
- “Presence” is **ambient continuity** (shared day state, quiet residue), not pushy liveness.

## THIS DOCUMENT DEFINES

Why AI-native calm properties should optimize for **durability and low obligation** instead of compounding interaction surfaces.

## CORE PRINCIPLES

- **Stability over growth**: more code paths should tighten defaults, not expand journeys.
- **Infra pass as hedge**: as more bundles land, **`invisibleInfrastructureStructuralThinning`** raises the floor for absence and ultra-thin modes（`civilizationStabilizedStructuralThinning` 为下一层护栏）。
- **Humanity without theater**: low-signal lines remain; civilization prevents them from stacking into performance.

## CODE ANCHOR

- Cross-cutting: `world-civilization-stabilization-layer`, `long-lived-internet-stability`, retirement + permanence layers feeding biases.

## WHY LONG-RUN COMPANIES NEED STABILITY

Growth-first AI products trend toward chat shells, memory stories, and onboarding loops. A civilization-stabilized stack trends toward **quiet infrastructure**: useful when ignored, fine when returned to rarely.

## MAINTENANCE NOTES

- When planning work, ask whether it increases **default quiet** or **attention debt**; prefer the former per `memory-protocol.md`.
