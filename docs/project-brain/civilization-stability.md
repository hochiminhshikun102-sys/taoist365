# Civilization stability

## QUICK CONTEXT BOOTSTRAP

- After calibration, the site needs a **long-horizon governor**: same deterministic inputs, less cumulative insistence over time.
- Stability means fewer accidental “system” reads—more **ambient default** without announcing governance.

## THIS DOCUMENT DEFINES

The **civilization stability** slice of `worldCivilizationStabilization`: fatigue resistance, non-expansion bias, and equilibrium language lived in data bundles—not user-facing essays.

## CORE PRINCIPLES

- **Ordinary longevity**: the goal is to feel like a calm corner of the browser, not a living dashboard.
- **Thinning is structural**: stability ships as numeric passes and gates; it does not ship as meta copy about “the site maturing.”
- **Layered pressure**: ecology tightens mutual limits; civilization stabilization **stacks** further thinning when explanation fatigue and cross-runtime suppression align.

## CODE ANCHOR

- Bundles under `src/data/civilization-stability-engine/` composed in `world-civilization-stabilization-layer/system.ts`.
- Civilization layer outputs **`civilizationStabilizedStructuralThinning`** (intermediate); UI consumes **`invisibleInfrastructureStructuralThinning`** (see `runtime-systems.md` §25–§26).

## WHY LOW AWARENESS MATTERS

Mature calm reads as **low consciousness**: nothing performs awareness of the visitor. That reduces companion drift, tutorial voice, and “return” theater—without adding new interaction layers.
