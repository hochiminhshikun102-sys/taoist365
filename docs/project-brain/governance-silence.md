# Governance Silence

This file exists to stop governance from becoming another atmosphere.

It should not be expanded unless a real drift appears.

## Purpose

Some rules have already been stated enough.

When a rule is stable, the next step is not a better name. The next step is to let it become ordinary maintenance.

## Stop Naming

Stop adding names when the thing already exists and works.

Do not rename or reframe:

- quiet internet;
- browser air;
- restraint-first work;
- ordinary presence;
- anti-performance;
- observation before repair;
- stable anchors;
- mail as human contact;
- objects as things, not products.

These should become assumed practice, not repeated slogans.

## Silent Governance

Silent governance means a rule remains active without being displayed.

It is:

- applied during review;
- checked when drift appears;
- used to say no;
- kept in memory;
- not turned into more copy.

It is not:

- a new layer;
- a new concept;
- a writing style;
- a public identity;
- a reason to produce more documents.

## Implicit Continuity

Some principles should now move into implicit continuity:

- quiet internet;
- browser air;
- restraint-first;
- ordinary presence;
- anti-performance;
- no feed;
- no companion behavior;
- no dashboard drift;
- no commerce pressure;
- no launch behavior.

Future work should use these rules without restating them every time.

## Documentation Should Thin

Documentation should become more like maintenance notes.

Prefer:

- short records;
- named drift;
- concrete repair;
- checks that can be run;
- decisions that help future work.

Avoid:

- manifesto tone;
- emotional texture;
- sacred framing;
- philosophical exhibition;
- repeating identity language;
- writing that makes restraint feel authored.

## Governance Is Not Atmosphere

Governance should not provide the feeling of the site.

If a document starts making the project feel more important, thinner wording is better.

If a rule is already clear, do not make it more beautiful.

## No Civilization Performance

Avoid:

- over-serious framing;
- repeated grand naming;
- sacred governance tone;
- conceptual self-importance;
- treating maintenance as a ceremony.

Long-lived structures usually become more ordinary over time.

## Disappearance Into Continuity

The goal of governance is to disappear into practice.

A good rule eventually becomes:

- a habit;
- a small check;
- a quiet refusal;
- a line in a review;
- a reason not to change something.

It should not become larger each time it is used.

## When To Write More

Write a new governance note only when:

- a new drift is observed;
- an existing rule failed;
- a future maintainer would be confused without it;
- a concrete boundary must be preserved.

Do not write more because the project feels meaningful.

## Governance Visibility Observation

Watch for governance becoming too visible.

Risk signs:

- documents explain themselves too much;
- rules keep receiving new names;
- restraint becomes a style;
- the project starts sounding like a philosophy archive;
- maintenance language feels ceremonial;
- ordinary decisions are written as worldview.

When this appears, remove framing before adding rules.

## Rule

If governance is working, it should become less noticeable.
