# Long-Term Browser Civilization Operating Layer

This file governs how Reverent Inquiry continues operating over time. It does not authorize new pages, runtime inflation, organism proliferation, feature orchestration, dashboards, or visible system intelligence.

## Operating Layer Governance

The operating layer is the coordination layer between governance, runtime, archive, production assets, Browser Air continuity, and memory handoff.

It exists to reduce thread-dependence and session-driven decisions. It should make future work boring, verifiable, and hard to deform.

Executable check:
- `npm run guardrail:operating`

## Runtime Orchestration

Runtime orchestration is the `buildRuntime()` chain in `src/lib/use-world-runtime.ts`. It should remain sparse, ordered, deterministic, static-export safe, and low-pressure.

Operating rule:
- do not add top-level runtime fields
- do not add resolver steps unless an existing resolver cannot absorb the responsibility
- prefer consolidation over new runtime files
- preserve resolver order unless the change is a deliberate governance decision
