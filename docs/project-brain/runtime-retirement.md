# Runtime Retirement

## Why runtimes must retire

Taoist365 stops **expanding** foreground expression: channels that once spoke daily move to **passive**, **residual**, **background permanent**, or **retired** phases. Retirement is **not deletion**—it is **default absence** so the URL reads as **stable**, not “under active development.”

## Implementation

- Path: `src/data/runtime-retirement-system/`
- Root: `resolveRuntimeRetirementBundle(...)` in `system.ts`
- Inputs: `structuralSilence`, `aging`, `inertia`, `worldRegulation`, `worldStability`, **`worldStabilityEngine`** (retirement pressure scaled by `engineStabilityScalar`), `browserReality` (for sediment → object retirement).

## Channel registry

`channelRetirement` maps logical channels (`guidanceResidue`, `humanTraces`, `ritualTeaching`, `mailExplain`, `objectMemory`, `browserRevisit`) to phases: `foreground` → `passive` → `residualOnly` → `backgroundPermanent` → `retired` → `archivePresence` (deterministic from day key + pressure).

## World fatigue & rest

- `worldFatigue.fatigueLevel`: `active` | `thinning` | `tired` | `resting` | `almostAbsent`
- `worldRest.restDay`: many runtimes may stay absent—**low energy day**, not broken layout.

## Guidance retirement surface

`guidanceRetirement.ultraMinimalRoom` — reflect UI becomes **weather + optional label + one line + home link** only.  
`forceZeroNoticing` — caps noticing lines to zero under heavy channel / ultra rules.

## Object retirement

`objectRetirement.rareForegroundObjects` — **1–3** ids sliced from sediment list by fatigue; `ObjectRuntimeGate` requires membership. **No catalog completeness.**

## Bans

- Runtime bloat as product feature, self-aware “the system is scheduling itself” copy, monastery / slow-web elitism (see `anti-meta-governance.md`).
