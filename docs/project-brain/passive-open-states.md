# Passive Open States

## Definition

A **passive open state** is when a page is **allowed to stay open** without implying the user should **act**, **finish**, or **progress**. It is not inactivity tracking, not idle timeout, not “come back soon.”

## Data

- `browserReality.browserSilence`: `browserQuietness`, `nonInteractiveComfort`, `passiveOpenState`, `longPauseLegality`
- `browserReality.guidancePassiveSurface`: session-specific flags for Pause **session** route

## Guidance session behavior

When `guidancePassiveSurface.passiveOpenGuidance` is true (typically `residualOnly` breathing or very quiet page energy):

- Routes can be **hidden**; closure / routing footer blocks can be **hidden**; “continue reflection” can be **hidden**; climate/rhythm **layers** can thin.
- `maxNoticingHardCap` may force **0–1** noticing lines after other gates.
- Primary exit can read as **minimal label** (e.g. “今晚先到这。” / “Enough for tonight.”)—still a normal link home, not a streak reward.
- `GuidanceSessionRhythmBanner` **does not render** in this mode so the session reads as a **state surface**, not a guided flow.

## Non-goals

- Sad minimalism, philosophy flex, or “the site is so quiet” performance (see `anti-performance.md`).
