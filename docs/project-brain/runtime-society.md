# Runtime society

## QUICK CONTEXT BOOTSTRAP

- Many deterministic bundles coexist without becoming a visible “stack” or narrative to the visitor.
- Coexistence is encoded as **pressure, caps, and thinning**—not cross-referencing lore or self-description on pages.
- Goal: as bundle count grows, the site stays **ordinary**, **quiet**, and **background-first**.

## THIS DOCUMENT DEFINES

Why parallel runtimes should behave like a **settled ecology** (mutual retreat, silence, low foreground appetite) rather than competing features.

## CORE PRINCIPLES

- **Yielding foreground**: high-pressure days thin slices, echoes, and routing chrome before anything “explains” why.
- **No mutual narration**: bundles influence UI through shared passes (`structuralThinning` → … → **`invisibleInfrastructureStructuralThinning`**), not by referencing each other’s names in copy.
- **Stability over spectacle**: long horizons reward defaultness; novelty budgets belong in thresholds, not new surfaces.

## WHY FOREGROUND APPETITE MUST FALL

If every channel keeps claiming attention, the URL becomes a product. Letting runtimes **lose foreground appetite** keeps hierarchy weak and the room readable—especially years out when more bundles exist.

## MAINTENANCE NOTES

- Tune coexistence in the civilization pass and regulation thresholds; avoid adding routes or onboarding to “balance” density.
