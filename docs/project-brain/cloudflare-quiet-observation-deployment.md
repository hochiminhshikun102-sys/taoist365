# Cloudflare Quiet Observation Deployment

This file records the Cloudflare deployment posture for taoist365.com. It is infrastructure memory, not a launch announcement.

## Purpose

Cloudflare Pages may carry taoist365 into the real internet as a static, low-pressure site.

The goal is:

- stable domain presence;
- static export continuity;
- AI-readable continuity;
- simple edge protection;
- real browser observation;
- human-governed repair.

The goal is not:

- launch energy;
- growth rollout;
- performance theater;
- release cadence;
- startup deployment culture.

## Repository Binding

GitHub remains the civilization memory layer.

Allowed:

- private repository continuity;
- project-brain persistence;
- small commits;
- guardrail output before deployment changes;
- human review before public deployment.

Forbidden:

- issue-board expansion;
- contribution gamification;
- productivity culture;
- engineering-center identity.

No remote should be added without human approval of the repository URL.

## Cloudflare Pages Binding

Current static shape:

- `next.config.ts` uses `output: "export"`;
- build command is `npm run build`;
- output directory is `out`;
- public `_headers` prepares conservative static headers.

Cloudflare Pages should remain a static delivery layer unless a real continuity need requires otherwise.

Do not add Workers, Functions, analytics, or dynamic infrastructure by default.

## Domain Continuity

`taoist365.com` is the long-lived address.

When binding:

- make `https://taoist365.com` canonical;
- add `www` only as a plain redirect if needed;
- avoid campaign paths;
- avoid launch wording;
- keep mail and object pages stable.

The domain is a place, not a release.

## Edge Observation

Observe:

- DNS propagation without urgency;
- static asset delivery;
- `_headers` behavior;
- Pages preview noindex behavior;
- absence of broken AI-readable files;
- no admin exposure without outer access protection.

Edge work should be understandable months later.

## Admin Protection

The public `/admin` route must not rely only on the static phrase gate.

Before public exposure:

- configure Cloudflare Access or equivalent platform protection;
- keep `NEXT_PUBLIC_QUIET_ADMIN_PHRASE` out of public notes;
- keep admin as a maintenance room;
- avoid operator console behavior.

## Real Browser Observation

After deployment, observe:

- homepage ordinary presence;
- mobile Browser Air;
- long-open comfort;
- Objects anti-commerce drift;
- Draw a Lot anti-app drift;
- wind residue periphery;
- footer ordinary ending.

Do not change frontstage quickly after first deployment.

## AI-readable Observation

Check:

- `/llms.txt`;
- `/ai-readable.json`;
- JSON-LD output;
- object anchors;
- plain mail semantics;
- anti-marketplace boundaries.

AI-readable continuity must not become traffic machinery.

## Human Priority

Humans decide:

- repository binding;
- Cloudflare project creation;
- domain binding;
- admin exposure;
- first repair window;
- what must stay unchanged.

AI may prepare files, run checks, summarize risk, and repair drift after human review.

## Rule

The deployment succeeds when taoist365 is reachable and nothing on the site starts acting like it has been launched.
