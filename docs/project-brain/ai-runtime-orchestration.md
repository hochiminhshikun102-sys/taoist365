# AI runtime orchestration（AI 运行时编排）

## 快速对齐（QUICK CONTEXT）

- **编排（orchestration）** 在这里指：多路 deterministic bundle（数据束）如何在同一天键下**错峰、退让、共存活**，而不是后台控制台或可视化工作流。
- 代码里是 **`src/data/ai-runtime-orchestration/`** 的文案原子 + 上层 **`world-ai-native-infrastructure-layer`** 的 **`invisibleInfrastructureStructuralThinning`**（不可见基础设施变薄 pass）—无面板、无「系统在跑」叙事的页面文案。

## 本文件定义什么

为何要让 runtime **被编排**：避免平行堆积成「功能竞技场」，把协作压在**阈值与变薄链**里完成。

## 核心原则

1. **不可见**：编排结果体现在 Daily / Guidance / Mail / Objects 的安静程度上，不体现在 explain-the-stack 的段落里。
2. **自治协作**：各 bundle 通过共享的 **`StructuralThinningPass`**（结构变薄 pass）链协商 foreground（前台存在感），不互相指名道姓。
3. **红线**：禁止 chat-shell UI、禁止 orchestration 可视化、禁止 meta runtime prose（元叙事式 runtime 说明）。

## 代码锚点（CODE）

- `src/data/ai-runtime-orchestration/*` — `resolveAiRuntimeOrchestrationBundle()`
- 变薄终点：`worldAiNativeInfrastructure.invisibleInfrastructureStructuralThinning`（UI 最终）

## 必须记住的结论（与用户阶段对齐）

- 长期价值更多来自 **治理与编排约束**，而不是把「AI 能力」摊在用户脸上。
